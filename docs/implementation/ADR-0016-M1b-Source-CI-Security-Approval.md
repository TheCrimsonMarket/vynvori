# ADR 0016 — separate M1b source/CI security approval

2026-10-19. Implemented selectors remain UNACTIVATED. No risk acceptance or deployment is authorized by this ADR.

M1b cannot borrow the existing M2 source/dependency/image approval. A separate proposed gate pins the complete current source, manifests, physical dependency resolutions, full unfiltered production/all audit graphs, image file/binary inventory, configuration, base layers and fresh unfiltered scan. It verifies the reviewed source against immutable implementation Git objects and permits only the two explicit M1b activation selectors to change after sealing. Existing M2 policy JSON and its original evaluator remain unchanged.

Scope is Linux GitHub pull-request CI for TheCrimsonMarket/vynvori, codex/m1b-central-identity → main, with every operational flag off, local Docker and no live M1b configuration. Vercel, Cloud Run, production, forks/other branches, partial audits, unreviewed registries, credential contexts and remote dependencies are rejected. This gate authorizes no runtime enrollment or staging operation. Its absolute proposed deadline is2026-10-24T23:59:59Z, without extending the existing private-staging review window.

The proposal includes only the known braces/sprintf production advisory roots and the nested esbuild development root. No critical finding may be accepted; image OS findings are capped at31LOW/MEDIUM entries and language findings at the exact known braces/sprintf advisories and versions. All actual records remain pinned, without severity/unfixed suppression. Data-only policy edits cannot broaden those caps. Fixed advisory availability or changed findings require review, not automatic reconciliation.

A read-only-permission evidence workflow checks out the exact PR head, installs dependencies, runs both unfiltered audits, builds an ephemeral local native image, inventories it and downloads a fresh vulnerability database for scanning. Its published output is an unapproved proposal with sanitized JSON evidence. It never writes an active policy, accepts its own result, publishes an image or deploys. A failed download/scan fails collection; there is no stale-cache fallback. Private image archives are removed by the existing image verifier and are excluded from uploaded artifacts.

After the actual evidence is available, the founder must review and separately authorize the exact source/risk proposal before an active policy file and selector literals may be committed. Source-only draft PR approval does not satisfy that gate. The existing source audit command remains rejecting while selectors are UNACTIVATED. Rollback deactivates the M1b selectors, retaining evidence and all M2 approvals; it does not weaken source validation or activate a runtime fallback.
