## Development and operators

From root: `npm ci`, `npm run dev:web`, `npm run dev:medusa`, `npm run dev:worker`, `npm run build:m2`, `npm run typecheck:m2`, `npm run test:m2`. Configure service-specific environment in the terminal/secret manager; Medusa can load its own `.env` using the placeholder template. Never copy infrastructure secrets to public variables or production Preview integrations.

Required environment (values are placeholders in `.env.example`):

- All adapters: `M2_ENV=local|staging`; production is rejected. M0 operational flags remain false/unset.
- Creative DB: `M2_CREATIVE_DATABASE_URL`; fixed database `vynvori_creative_staging`. Staging additionally requires exact `M2_CREATIVE_DATABASE_HOST`, pooled Neon hostname and `sslmode=verify-full`. Use a dedicated creative role; never give it Medusa DB access.
- Medusa: `M2_MEDUSA_DATABASE_URL`, `M2_MEDUSA_DATABASE_NAME`, staging `M2_MEDUSA_DATABASE_HOST`, independent `M2_MEDUSA_JWT_SECRET`/`M2_MEDUSA_COOKIE_SECRET` (32+ characters), exact `M2_MEDUSA_STORE_CORS`/`M2_MEDUSA_ADMIN_CORS`/`M2_MEDUSA_AUTH_CORS`. Cloud-managed database settings need mapping to these explicit fields after provisioning review.
- R2: `M2_R2_ACCOUNT_ID`, `M2_R2_BUCKET` (`vynvori-staging-*`), `M2_R2_ACCESS_KEY_ID`, `M2_R2_SECRET_ACCESS_KEY`; private staging bucket only, scoped object permissions, no public domain/r2.dev access. No presigned/customer endpoints.
- Worker: `M2_PROCESSING_TOKEN`, `M2_ENV`; operator client also needs `M2_PROCESSING_ORIGIN` and staging `M2_PROCESSING_ID_TOKEN` (short-lived Google identity token for exact service audience). Token rotation is operational, not a static repository key. `cloud-run.yaml` has REQUIRED placeholders and is not applied automatically.

Generate/review SQL: `npm run db:generate`; check metadata: `npm run db:check`. Apply only after verifying isolated target/backup with `M2_APPLY_MIGRATIONS=vynvori-creative-staging npm run db:migrate` (PowerShell: set environment separately). It uses Drizzle's migration history and is replay-safe. No `db push`, destructive SQL or production target. Future user/session/creative/ledger/assets/QA/outbox schemas remain proposed canonical documentation; none is prematurely implemented here.

`npm run smoke:m2` is an operator CLI, never a public route. It returns only version/service/status/code and fails if any dependency is unconfigured/unavailable. Storage smoke uploads/reads/deletes a fixed synthetic PNG; it must reconcile any uncertain write/delete before rerunning. `/api/health` remains exactly the M0 liveness contract. Medusa `/health` likewise proves process liveness only. DB readiness checks its schema and database; worker readiness means synthetic mode only. Availability never enables a feature flag.
