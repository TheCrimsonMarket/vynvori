# ADR-0017 — M3 composition scene persistence and BYO editor

Status: implemented locally, **not deployed**. Base commit `ad6392aaa7785e34fb5fa10c62b66c1c1f7e4a71`. Branch `claude/m3-byo-garment-editor`.

## Decision
- **Scene contract** lives in `@vynvori/contracts/composition-scene` and *builds on* the merged `editor.ts` layer schemas. Geometry is millimetres, origin top-left, rotation about box centre, quantised to 1 µm. Canonical JSON sorts zones/layers/keys; `sceneHashSha256 = SHA-256(canonical JSON)` (computed server-side in `@vynvori/commerce/composition`). Image layers pin `sourceAssetSha256`; text layers pin font file hash + licence version against a typed registry (only bundled OFL-1.1 Archivo).
- **Print profile is preview-only by construction.** `PrintProfileV1` has no approved status; `supplierApproved`/`printReleaseEligible` are literal `false` in Zod *and* `CHECK` constraints. The single profile is `SYNTHETIC_PREVIEW_PROFILE`, a 200 × 260 mm frame taken from the approved design simulation's illustrative zone — **not** supplier data. Preflight can only return `preview_only` or `blocked`, never `passed_pending_human_qa`.
- **Neon schema `vynvori_composition`** (migration `packages/db/composition-migrations/0001_composition_scene.sql`): `print_profiles`, `compositions` (mutable draft + `lifecycle_state` limited to the four M3 Plane D states), `assets` (immutable, private R2 keys), `composition_versions` (immutable snapshots; trigger rejects UPDATE/DELETE/TRUNCATE; trigger requires pinned asset hashes to belong to the same composition). Ownership = verified-SSO `owner_user_id` **or** an unclaimed, unexpired M1b `guest_drafts` capability; every statement carries the access predicate in SQL. FKs are `ON DELETE RESTRICT`. No FK to Medusa.
- **Plane D** is enforced in the service with `canTransitionPlaneD` (guest_draft → editable_scene → saved_owned → frozen_version; frozen never mutates, editing returns to editable_scene). `composition_quoted…ordered_snapshot` are rejected by CHECK until M4.
- **Guest/owner rights.** Guest capability: random 256-bit, only its SHA-256 stored, delivered in an HttpOnly `__Host-` SameSite=Strict cookie (never in JSON). Claim = M1b `claimGuest` **and** capability hash **and** same verified user; afterwards the capability stops working. Absent/foreign/expired all return the same NOT_FOUND.
- **Assets.** `inspectImage` decides type from magic bytes, verifies PNG chunk CRCs / JPEG EOI / WebP RIFF size, rejects SVG, GIF, PDF, animation, trailing bytes, >25 MB, >36 MP / >20000 px. Originals are stored unchanged, content-addressed, write-once (`If-None-Match: *`) at `private/composition/v1/{compositionId}/{sha256}`; reads stream through the API with ownership check, `nosniff`, `sandbox` CSP, `no-store`; no presigned/public URL exists. The M2 synthetic adapter is **unchanged**; `composition-storage.ts` reuses only `r2Target`.
- **Flags.** `assets.production_uploads` stays `false` and unsettable. The composition API is closed unless the isolated staging identity canary **and** `M3_COMPOSITION_ENABLED=true` are present, never on production; uploads further need `M3_COMPOSITION_UPLOADS=true`. With everything OFF `/customize` is a fully working **local-only** editor (nothing uploaded or stored) and shows that honestly.
- New workspace edges only: `@vynvori/contracts` added to `commerce`, `db`, `web` (+1 line each in lockfile; `test:security-policy` still 34/34). No new third-party dependency.

## API (new; `docs/technical/16-api-contracts.md` shapes)
`POST/GET /api/v1/compositions` · `GET/PUT …/:id` (`expectedRevision`) · `POST …/:id/versions` (freeze) · `GET …/:id/versions/:versionId` (ED-03 projection, preview-only, no proof/quote/cart) · `POST …/:id/restore` · `POST …/:id/claim` · `POST …/:id/assets` · `GET …/:id/assets/:assetId`. Mutations require same-origin; session callers also need the M1b CSRF double-submit. No events emitted.

## Rollout / rollback
- **Rollout is NOT authorised by this change.** The migration runner (`applyCompositionMigrations`) accepts only loopback disposable databases and pinned SQL SHA-256. Applying to staging Neon needs a separate founder remote-database approval, a pinned target added to the plan, and runtime-role grants (SELECT/INSERT/UPDATE on `compositions`; SELECT/INSERT on `assets`, `composition_versions`, `print_profiles`; USAGE on schema; cross-schema SELECT/UPDATE on `vynvori_identity.guest_drafts` as M1b already uses; INSERT on `guest_drafts`). Take a native PG backup first (M2 procedure).
- **Rollback:** code — revert the PR (flags OFF means no live path). Data — `composition-migrations/rollback/0001_composition_scene.down.sql` (manual; refuses while any composition/asset/version row exists, otherwise drops the schema). Orphan R2 objects (upload succeeded, row insert failed) are content-addressed and idempotently retried; a sweeper is future work.

## Consequences / open items
Rate-limiting of anonymous draft creation, malware scanning, derivative/thumbnail generation, signed expiring URLs and the deterministic text renderer are not implemented (M5/edge). Editor text is an SVG approximation. `EditorLayerV1` has no lock/opacity/crop fields, so those editor tools are not offered.
