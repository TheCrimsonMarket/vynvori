# M2 read-only Medusa catalog verification

2026-10-17. Base `72360665652fbf61a0a571fc876db192f060f9a4`. Executable operator tooling; remote execution NOT_RUN. This adds no runtime service, public API, event, dependency or migration. Architecture remains ADR-0005; no new architecture decision is introduced.

Run `node scripts/medusa-catalog-cli.mjs` in an existing protected operator environment with `M2_ENV`, `M2_MEDUSA_DATABASE_URL` and, for staging, `M2_MEDUSA_DATABASE_HOST`. Do not place a password-bearing URL on the command line or paste the report's credentials into documentation. The tool does not load `.env` or fetch cloud secrets. Staging requires the pinned direct Neon host, exact `vynvori_medusa_staging` database, `vynvori_medusa_runtime_scoped` login and verify-full TLS; owner/migration logins and migration mode reject. It needs no JWT/cookie secret or cloud IAM expansion.

The tool connects once with a three-second connection/statement limit, four-second client query limit and twenty-second overall disconnect deadline. It opens `REPEATABLE READ READ ONLY`, verifies actual database/session/current role and read-only mode, reads PostgreSQL catalogs and rolls back on success or failure. Each inventory is bounded to 10,000 rows; oversized results fail instead of silently truncating evidence. The CLI reports generic failure without SQL, URLs, credentials or driver errors, and emits no partial report.

Output version 1 always says `REVIEW_REQUIRED`, including empty/unmigrated catalogs and unsafe privileges. It includes effective runtime table/sequence privileges (including inherited/PUBLIC effects), memberships, elevated role flags, TEMP/schema-CREATE capability, owners/raw object and default ACLs, sequence SERIAL/IDENTITY dependencies and public function signatures/EXECUTE/security-definer metadata. Domain rows, function bodies, passwords, connection URL and tokens are excluded. Keep the metadata report in restricted review evidence; it is not customer-facing. Additional schemas, extension behavior, function bodies/search paths, indirect privilege paths, actual operation necessity, object defaults and control-plane branch identity still require review. This is evidence collection, not a complete privilege-security certification.

For an independently authored proposal, import `bindGrantProposal` from `scripts/medusa-catalog.mjs` and `runtimeGrantProposal` from `scripts/medusa-runtime-grants.mjs`. Pass the proposal through `bindGrantProposal(objects, catalog)` first, then `runtimeGrantProposal(...)`. The first rejects absent/duplicate/foreign-owned objects and wrong sequence parent dependencies; the existing builder restricts privileges and bookkeeping access. Neither executes SQL. A supplied JSON report is not proof of authenticity or freshness: retain raw report hash, timestamp, exact source and provider target mapping for independent review. Approval/application of explicit grants remains separate.

Unit/error/redaction tests are included in `npm run test:staging`. Real PostgreSQL integration is opt-in with `M2_CATALOG_TEST_ADMIN_URL` and must use a NEW disposable loopback database named `vynvori_medusa_staging`. The test creates synthetic roles/tables/function and must never target an existing application database; its assertion rejects nonloopback/wrong-database URLs before connecting. This fixture creation is distinct from the operator collector, which executes no mutations. The executed test used PostgreSQL 17.6 in a new label-scoped container, tested the real CLI afterward, and removed that container. Standard CI/default tests label the integration skip explicitly when the isolated fixture URL is absent.

Security review: fixed catalog SQL only, no interpolated operator input; strict runtime target/TLS checks; no migrations/grants in the CLI; no retry; rollback and connection close before successful output; fail-closed bounded output; unchanged sealed policy/remote gate; no production activation. Synthetic test SQL uses fixed role/fixture literals only. Remaining risks are metadata confidentiality, operator-supplied environment/catalog provenance, provider permissions and unreviewed function/default privileges. No independent review or remote acceptance is asserted.

Rollback is a normal revert of this tooling/test/script-registration batch. No database rollback is necessary because operator collection is read-only. Existing migration/grant review requirements and all production flags remain unchanged. Follow [the unified ledger](MILESTONE-PROGRESS.md) for actual test/PR state.
