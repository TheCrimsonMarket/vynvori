## What the candidate changes

Portal adds a strict, default-off contract with server-owned enrollment, issuer/client/audience binding, current subject token-version checks, exact callback/S256 context, single-use refresh rotation, family revocation, replay/lost-response handling, persistent generation fencing and explicit rate limits. Startup/request handlers perform no index creation/repair. Activation checks the new strict indexes and the existing code-uniqueness constraint read-only. Preparation of the two new collections is an explicit operator-only function requiring the exact database name.

The core proxy removes credential prefixes, cookies, request payloads and raw exceptions from diagnostic logs. Successful legacy GET/POST, public 4xx, unexpected-error response contracts and shared upstream selection remain intact, including when new enrollment settings are malformed. Strict behavior requires explicit server enrollment and exact HTTPS web/API origins; it rejects hostile/missing POST Origin, caller-supplied provenance/context/credentials and duplicate query parameters. Strict cookies cannot fall back to the shared legacy `API_URL`; redirects are disabled and unexpected strict responses are sanitized/no-store.

An anonymous read-only request to the current public development `/mana/oauth/authorize` returned 404. The candidate therefore adds that public alias **only when strict mode is configured and only for the enrolled strict cohort**, with the same session/context guard and a bounded JSON consent parser. Existing internal `/oauth/authorize` and legacy token/refresh/revoke behavior remain supported. This alias is local candidate code, not a claim about a deployed endpoint.
