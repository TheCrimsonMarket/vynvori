# Dataset and screening protocol

Four versioned briefs: ARPG-01 cartography emblem with a separate editable phrase; MIN-02 restrained gothic geometry; CHAR-03 original lantern courier mascot; MOOD-04 psychedelic fantasy synthesis. Each includes intent, palette, exclusions, symbolism, garment context, zone and native raster expectations.

The operator authorized locally created procedural references. Twelve PNGs (three per case) are created from palette swatches, abstract portal geometry and organic contours. `LICENSES.csv` records origin, rights, dimensions and SHA-256. There are no game logos, copied characters, photos or private user assets. This tests abstract visual direction, not sophisticated photographic moodboard interpretation.

Every concept model receives the same authored prompt and identical three reference files for that case. Adapter shaping changes transport fields only. Both authored and sent prompt text/hash are retained. The generation brief excludes raster text; the exact “I’m only mapping.” phrase belongs in the editable typography layer. No provider-specific prompt tuning or hidden prompt expansion is used.

Budget revision: original blueprint 56-operation pilot is replaced by a screen with one trial per model/case (16 successful concepts intended). Nano Banana 2.1's two zero-charge 429s remain separate. Its explicitly documented Nano Banana 2 replacement uses the same briefs/reference inputs/settings. Operator then authorized 12 follow-ups, two controlled edits plus one final for each working family. This is still a small exploratory sample, not a repeat-trial superiority study.

Edit/final comparison uses one predeclared common OpenAI CHAR-03 source, chosen before quality ranking to hold input bytes constant. It is not a founder-accepted production asset. All four candidates receive the same source image and the same color-change/local-star instructions. Each edit independently starts from the original, avoiding sequential-edit confounding. Final renders also start from that original.

Concepts target 1K square where resolution is supported; OpenAI uses its documented medium/1:1 settings with actual dimensions recorded. Final requests target 2K portrait for Google/FLUX/Seedream and high/3:4/transparent for OpenAI. Different native controls are reported rather than misrepresented as identical pixel/quality settings. Previews and finals are analyzed separately.

Blind samples receive cryptographically random IDs and a deterministic random-looking order based on their hashes. Review canvases use identical black 768 × 1024 backgrounds. Separate native-size derivatives permit edge/alpha review. Provider metadata is omitted only from review derivatives; exact originals remain untouched. The secret mapping is outside the scoring folder. Two raters independently submit scores before unblinding. Large disagreement (>1 quality point) requires adjudication and is excluded from acceptance pending resolution.
