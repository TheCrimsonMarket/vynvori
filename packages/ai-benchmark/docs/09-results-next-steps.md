# How to finish the founder decisions

1. Give each of two reviewers only `results/review`, dataset fixtures and the evaluation rubric. Open `blind-review.html`, score independently, and save the two JSON files. Keep `data/blind-mapping.json`, raw ledgers and costs hidden until scoring is complete.
2. From the original workspace or packaged `code` directory, import `npm run benchmark -- scores reviewer-1.json`, then the second file. Resolve major disagreement rather than averaging away a defect.
3. All four tested finals fail the provisional full-zone 300-PPI target. Native effective PPI is about 98–152; only the OpenAI final has meaningful alpha. Decide with the actual printer whether smaller placements, a tested background/edge-cleanup plus upscale/vector workflow, or different rendering specs are appropriate. Do not silently lower the selected gate. Physical DTF testing is still required.
4. Inspect `api-session-baseline.csv` for measured API-only 3-concept/2-edit/1-final estimates. It is not cost per accepted design and excludes production fixes. Import provider usage exports/receipts to upgrade billing evidence.
5. Once qualified accepted costs and full allocations are known, copy `config/economics.example.json`, replace every null with measured/explicit scenario inputs, and run `npm run benchmark -- economics assumptions.json`. This produces 18 standard/premium × base/conservative/high-retry × 3/3.5/4 sensitivity rows, including integer credit rounding, payment fees, redemption and minimum top-up. `paymentFixedUsd` is the amount allocated to that guided session, not automatically the full fee on every generation event. Values entered here are scenarios, not a live price table.
6. Keep US production routing for Seedream blocked until the exact reseller/territory contract is clarified. Activate fal only after a specialized endpoint is selected and separately funded/authorized.

For practical provider management, use the existing funded OpenRouter account first and preserve fal as an optional specialized second integration. Do not migrate to many direct accounts solely to repeat this small experiment.
