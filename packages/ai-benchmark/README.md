# Vynvori image-model benchmark

A local TypeScript CLI for an auditable, bounded image benchmark. Live outputs and human decisions are separate. Dry runs contain no generated artwork. Model quality winners and production credit prices remain unset until review.

Run commands from the workspace root with Node 22.23+:

```powershell
npm.cmd ci
npm.cmd run typecheck
npm.cmd test
npm.cmd run benchmark -- dry-run
Copy-Item .env.example .env  # once; edit locally and never share its contents
npm.cmd run benchmark -- check-key
npm.cmd run benchmark -- run --live --stage smoke
npm.cmd run benchmark -- run --live --stage concept
npm.cmd run benchmark -- followups packages/ai-benchmark/config/selections.json
npm.cmd run benchmark -- dry-run --stage followups
npm.cmd run benchmark -- run --live --stage followups
npm.cmd run benchmark -- export
```

The key must have a lifetime limit <= $9.50, no periodic reset, and enough remaining balance for each planning allowance. The operator authorized $10 total with a $0.50 reserve. fal's current cap is $0 and live fal calls are disabled. A provider-side credit limit is checked before each submission; planning allowances are conservative operational reservations, not mathematical maxima for token-billed models. Do not share the benchmark key with other workloads.

`run` without `--live` stays offline. Requests are sequential, with a four-minute timeout and no automatic POST retry. A single confirmed zero-charge HTTP 429 may be deliberately retried with `--retry-rejected`; completed, uncertain, and charged failed tasks cannot be resubmitted. `--only-model EXACT_ID` and `--exclude-model EXACT_ID` narrow the experiment without changing routing. A stale `.runner.lock` after a killed process must be investigated with the ledger before manual removal.

The Nano Banana 2.1 endpoint returned two zero-charge 429s. `scripts/amend-google.mjs` registers Nano Banana 2 as a separate replacement and records the amendment. Do not rerun `prepare` on an existing experiment: it restores the original initial setup. Existing fixtures/configs are checked in for reproduction. Research refresh and amendments require checking differences before additional paid calls.

Review `results/review/blind-review.html` with two independent raters. Give raters only results/review and rubric, not raw costs/model names or the mapping. Each rater downloads a JSON file. Import separately:

```powershell
npm.cmd run benchmark -- scores path/to/reviewer-1.json
npm.cmd run benchmark -- scores path/to/reviewer-2.json
```

Original provider bytes and extension-identified copies live in `results/artifacts/`. The blind review creates separate PNG derivatives without provider metadata. `results/private/blind-map.json` links anonymous samples to run IDs. Keep this mapping away from raters until scoring is complete. The unmodified originals preserve provenance and watermark/content credentials.

Reconciliation accepts a JSON file with `runId`, `status` (`completed` or `failed`), `amountUsd`, `evidence` (`invoice` or `usage`) and a nonempty `reference`. It resolves outstanding records and upgrades billing evidence on confirmed deliveries without changing their outcome; completion requires an already verified durable image. Use `npm.cmd run benchmark -- reconcile evidence.json`. The command does not send another generation request. If the provider completed a lost response but no artifact is recoverable, reconcile its charge as a failed delivery with the billing reference. Investigate and recover async jobs using their recorded provider request IDs before considering a new experiment.

Build the handoff/contact sheet using the bundled Python runtime with `reportlab`, `pypdf` and Pillow:

```powershell
python packages/ai-benchmark/scripts/build-handoff.py
```

Exports include every paid request, failed deliveries, estimates, exact source hashes, prompt text/hash, model ID, provider, output checksum, dimensions and technical print gates. No subjective score is generated by the agent. With native ~1K/2K outputs, the provisional 300 × 400 mm, 300 PPI print target may fail; an attractive preview is not production evidence.

Native REST adapters are intentional for the dedicated OpenRouter Images API's endpoint pinning and billing contract and fal's persistent queue. AI SDK 7.0.137 and Workflow 5.2.0 were verified on npm; production SDK/workflow integration is specified in the handoff rather than installed into this standalone CLI. The tests cover mocked fal execution; fal was not live-tested without funding.
